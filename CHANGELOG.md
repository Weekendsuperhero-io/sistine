# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed
- **Chakra renames (BREAKING)**: renamed the tint presets Emerald → Aventurine, Bone → Moonstone, and Neutral → Selenite to align the jewel palette with the chakra-stone set. The demo switcher migrates stored legacy names automatically, but consumers targeting `[data-glass-tint="emerald"]` / `[data-glass-tint="bone"]` must update to the new names.
- **Material system (BREAKING)**: redesigned the glass API around four **materials** (`glass`, `frosted`, `crystal`, `opaque`) selected with a `material` prop (undefined = adaptive glass, the default; `material="none"` = plain, non-glass), composed with orthogonal **axes**, `border`, `veil` (the legibility floor for menus/overlays), `gradient`, `glow`, `sheen`, while `size` stays the component's own dimension. On raw elements the surface is the single structural `glass` utility plus the `glass-border` / `glass-veil` / `glass-sm` / `glass-lg` / `glass-gradient` / `glass-glow` / `glass-glow-lg` / `glass-sheen` axis classes, with the material set via a `data-material` attribute. Components now live in **one tree** (`components/ui/*`) and resolve their surface through `materialSurface` / `glassMaterial` in `lib/material.ts` instead of hardcoded recipe-class strings. Renamed the crystal gloss attribute `data-crystal` → `data-gloss`. The page-style `data-glass` and tint `data-glass-tint` attributes are unchanged.

### Removed
- **Legacy glass API (BREAKING)**: removed the `variant="glass|frosted|crystal|opaque|surface|solid"` surface tiers, the recipe utility classes (`glass-bg`, `glass-surface`, `glass-solid`, `glass-opaque`, `glass-frosted`, `glass-crystal`), the per-component `glass={{ color, blur, transparency, outline }}` prop, replaced by the `glassVars({ tintH, tintC, tintA, opacity, blur, solidA })` helper that emits CSS custom properties, and the `components/ui/glass/*` wrapper tree.

### Added
- **ARC Bronze contrast**: introduced APCA contrast banding targeting for size-tiered text foregrounds and icons.
- **Perceptual hue helpers**: added `complement` and `harmony` OKLCH hue helpers for theme-complementary accents.
- **Glass surface tiers**: added `surface` and `solid` variants across all glass UI components.
- **Standalone icon utilities**: shipped `--foreground-ui` and the `text-foreground-ui` utility for standalone icons with optional hue tracking.
- **Theming documentation and tooling**: added an APCA verification oracle, an interactive `ForegroundTester`, and comprehensive theming guides.
- **Hue wheel presets**: added 5 new single-hue jewels (Carnelian, Peridot, Turquoise, Aquamarine, Tourmaline) to fill color gaps.
- **New frescoes**: introduced Aurora and Gloaming bespoke multi-hue presets for light and dark modes.
- **Theme regression guard**: introduced a test script in CI to verify scope invariants and theme synchronization.
- **Surface tiers switcher**: introduced a tunable surface switcher with a configurable solid glass floor.
- **Gradient text component**: shipped `@sistine/gradient-text` along with corresponding theme tokens and utilities.
- **Chakra jewels**: added Lapis (h 268, deep ultramarine between Sapphire and Amethyst) and Goldstone (h 22, coppery red between Rose and Carnelian) single-hue presets, filling the palette's two widest hue gaps.
- **Horizon scenes**: added three pure-CSS animated pattern backgrounds on the shared 42% horizon, all drawn from photographic references rather than illustration: `clouds` (a deep-blue altitude sky over a parallax cloud deck, with a placeable moon), `dune` (golden-hour ridges receding into haze, blowing sand, a placeable moon), and `aurora` (borealis curtains mirrored in rippling water below the waterline). None of the three draws a horizon *line*: the sky dissolves into the ground across a mottled haze band, and distant layers wash toward the sky's own value. All are light/dark aware, take a half-strength theme cast in the mid-sky, move on compositor-only transforms, and respect reduced motion. `clouds` and `dune` swap the disc per mode: a **sun** by day (a hot core with a wide bloom, sitting low in the warm band for `dune`) and a prominent moon by night, from one shared rule, and `dune` adds a **blowing-sand control** (`breeze` / `storm` / `still`) driving wind veils that stream across the ridges.

### Fixed
- **Blurry text on popper surfaces**: `dropdown-menu`, `popover`, `tooltip`, `select`, `hover-card` and `context-menu` are positioned by an inline `transform` that Radix does not round. Combined with the glass `backdrop-filter` (which promotes the surface to its own compositing layer), a fractional offset rasterized every glyph off the device pixel grid. A new `lib/snap-popper.ts` rounds the wrapper's translate to whole pixels and re-applies after each reposition. Same defect the dialogs had; there the fix was to centre without a transform, which a popper can't do because its position *is* the transform.
- **Moonstone night read as brown**: at the default opacity every surface (cards, inputs, the nav pill) paints `--glass-opaque-bg`, and moonstone's dark floor derived `oklch(0.8 0.047 75)`, a sand/tobacco tan rather than the pale silvery stone the preset is named for. Lightness alone could not fix it: h75 is a warm hue, so every lightness along it lands somewhere in the tan family; cutting the CHROMA is what moves it off that family. `.dark[data-glass-tint="moonstone"]` now sets `--glass-opaque-l: 84` (from 80: the "slightly lighter" half) plus `--glass-opaque-c-scale: 0.45`, deriving `oklch(0.84 0.021 75)`. Contrast improves rather than regresses: all five static `--foreground-*-opaque` tiers gain **+7.1 Lc** against the lighter floor, and `--foreground-strong-opaque` now clears the APCA body threshold at 75.0. Light mode is untouched (still `L 94` / `c-scale 1`, where the same hue reads as cream). The wash knobs are unchanged, so the `[moonstone-sync]` mirror in `auto-foreground.tsx` needs no update.
- **Gradient and canvas backdrops were unreadable at one end**: the ramps in `lib/oklch-utils.ts` deliberately cover their FULL range, which is what makes them useful as swatches; as a full-bleed wallpaper it meant `linear-gradient` ran from pure black (L 0) to pure white (L 100) across the viewport, so a single solved foreground could only be legible at one end. Backdrops now fit their ramp into `readableLightnessBand()`: the lightness range where text over them clears APCA 60, binary-searched against the live `--foreground` (so it tracks AutoForeground, the tint and the mode). Measured: light mode bands to L 83–93, dark to L 7–63. The band stops short of L 0 / L 100 on the high-contrast end, which costs no readability and keeps the tint from washing out to pure black or white at one edge. `rampAxisColors` is untouched, so the docs swatches still show the full range.
- **Conic gradients had a hard seam**: a conic wraps, so whatever sits at 360° butts straight into 0°. An open ramp met its own opposite end at the twelve-o'clock line and drew a hard edge through the wallpaper, at full range, white against black (measured seam ΔL = 1.0). Conic now closes the loop: the cyclic `hue` axis repeats its first color at 360°, the rest mirror out and back, and the center plateau is dropped since it reads as a lopsided wedge once bent into a circle. Seam ΔL/ΔC/ΔH now measure 0. Frescoes bypass the ramp, so they get the same clamp and loop-close applied directly.
- **Tint chroma went uncontrolled on the extreme surfaces**: sRGB's chroma ceiling depends on BOTH lightness and hue, so one `--glass-tint-c` scalar could not land equally across 17 presets. Two places asked far past what any hue can hold and let the browser's gamut mapping decide the result: the near-white sheet/border/crystal stack at L 95–100% (lapis delivered 9% of its declared chroma there where peridot delivered 98%), and `--glass-gloss-ink`, whose ×4.25 multiplier is calibrated for the default tint and reached `C=0.6375` on a preset, roughly double the maximum chroma sRGB holds at *any* hue. Added `--glass-tint-c-hi` (`min(var(--glass-tint-c), 0.025)`) for the 13 near-white declarations and clamped the gloss product to `0.3`. The default tint (0.018) sits under both and is unchanged; measured border chroma across every preset is 0–0.0015 either way, which matches the engine's own note that the sheet is too sheer to show a hue, the color comes from `--glass-tint-wash`, which is untouched. This is the CSS-side counterpart to the 3% margin `lib/oklch-utils` already carried for the computed path.

### Added
- **`pnpm test:dom`**: added vitest + Testing Library + jsdom (`vitest.config.mts`) for the cases that genuinely need a renderer, and 17 tests across three files. `tests/data-table.test.tsx` drives the react-table **v9** migration through the UI, paginate, sort both directions, filter, case-insensitivity, clear, because v9 moved the row models into a `tableFeatures()` registry and a missing feature or row-model slot does not throw: the control just silently stops working, which a type-check cannot catch. `tests/snap-popper.test.tsx` covers the DOM half of the popper snap (finds the Radix wrapper, re-snaps on rewrite, does not loop on its own write, disconnects on unmount, and `composeRefs` still reaches the forwarded ref). `tests/background-provider.test.tsx` pins `patternSand` cycling, including that it visits each value exactly once per lap, which a wrap-only assertion would miss. Tests live in `tests/`, not beside the components, because `components/ui/` is the published registry tree and has to stay shippable, verified: zero registry entries reference it.
- **Unit tests consolidated into vitest**: the pure-function checks (popper transform snapping, readable bands, ramp banding + conic seams, fresco stops) started as `scripts/check-units.mjs` because the repo had no test runner at the time. It has one now, so they moved into `tests/` where they belong; `scripts/check-units.mjs` and `pnpm test:units` are gone. Keeping them outside the runner bought nothing once vitest was a committed dependency, and it made the coverage invisible to anything scanning for test files. The CSS-invariant scripts (`check-theme`, `check-patterns`, `check-gamut`) stay as node scripts, they parse stylesheets rather than exercise functions.
- **Tests for the colour-picker focus fix and `bodyClassName`**: `tests/background-switcher.test.tsx` drives the keyboard path that was broken (focus with no pointer involved), that the hex tracks the live tint rather than a mount-time snapshot, and that a user-chosen colour is not clobbered on refocus. `tests/dialog.test.tsx` pins that `bodyClassName` reaches the body wrapper, merges with the defaults instead of replacing them, lets `flex` win over the default `grid`, and does not leak onto the outer surface.
- **`pnpm test:gamut`**: `scripts/check-gamut.mjs` scrapes every declaration composing tint chroma out of `engine.css`/`materials.css`, resolves each one's lightness per mode from `tokens.css`, and scores all 27 presets against the sRGB ceiling at their hue (20 surface/mode pairs). It asserts nothing about intent: asking past the ceiling is legitimate and delivered chroma keeps rising with the request, so the thresholds are baselines pinned just above today's worst case and the check fails on **drift**, a new preset or retuned multiplier reaching further out than anything shipping now. Wired into `pnpm test`.

### Fixed
- **Popper observers were rebuilt on every render**: the six popper surfaces composed their refs with `ref={composeRefs(ref, snapRef)}` written inline, which hands React a new callback identity each render. React responds by detaching the old ref (calling it with `null`) and attaching the new one, and that detach runs `useSnappedPopper`'s cleanup, so the `MutationObserver` watching the popper wrapper was torn down and rebuilt on *every* render of *every* popper. Added `useComposedRefs` (same shape as Radix's own: `useCallback` over the composed callback with the refs as the dependency array) and moved all **8** call sites across the six components onto it. Kept local rather than importing `@radix-ui/react-compose-refs`, since these ship through the registry and a direct dependency would have to be declared on all six.
- **`DialogContent` gains `bodyClassName`**: the inner scroll wrapper added for the overflow fix forced `grid gap-4` onto every dialog body, and `className` targets the outer surface, so consumers had no way to reach it. `bodyClassName` styles the wrapper: swap the grid for flex, drop the gap, or take the scrolling over entirely.
- **Colour picker default ignored keyboard users**: the themed hex was applied on `onPointerDown`, which never fires for someone tabbing to the swatch and pressing Space/Enter; they opened the picker on a stale value. Moved to `onFocus`, which precedes activation on both paths.

### Security
- **PR review workflow no longer inherits every secret**: `.github/workflows/pr-review.yml` used `secrets: inherit` on a job that triggers on `synchronize`, so every push to a PR branch ran the reusable workflow with the repository's full secret set. Now passes only the three the review agents actually need, `JULES_API_KEY`, `JULES_PR_CLIENT_ID`, `JULES_PR_PRIVATE_KEY`, explicitly, so adding a secret to the repo cannot silently widen this workflow's blast radius.
- **Reusable workflow pinned to a SHA**: it referenced `platform-tools/.github/workflows/reusable-pr-review.yml@main`, a mutable ref that runs with this repository's token and secrets; any push to that repo's default branch would execute here unreviewed. Pinned to `72bbd12`, with the branch and date kept as a trailing comment.
- **Popper surfaces scaled from their centre**: `popover`, `tooltip`, `select` and `hover-card` play a `zoom-in-95` entrance but never set `transform-origin`, so they grew from their own middle instead of from the trigger that opened them. Each now reads Radix's own `--radix-<component>-content-transform-origin`, matching what `dropdown-menu` and `context-menu` already did. `select` sets the variable only in `position="popper"` (its default); under `item-aligned` the variable is undefined, `transform-origin` computes to its initial `50% 50%`, and that mode keeps centre-scaling, which is what it wants.
- **Reduced motion**: the looping animations outside the pattern scenes now honour `prefers-reduced-motion`: the skeleton shimmer stops, spinners slow rather than freeze (a frozen loader reads as hung), and the opacity-only `pulse` is deliberately left alone. The pattern scenes additionally release `will-change` when motion is off, instead of holding a promoted compositing layer for an animation that isn't running, the speed control's **Static** setting releases it too.

### Added
- **Declared browser support**: `browserslist` in `package.json` (Safari 17.5+ / Chrome 120+ / Edge 120+ / Firefox 128+), derived from the features the theme actually uses rather than chosen: `text-wrap: balance` sets the Safari floor, bare-`&` CSS nesting and unprefixed `mask-composite` set Chrome's, `@property` sets Firefox's. Documented in the README with the per-feature reasoning, plus a single `@supports not (color: oklch(…))` safety net so an engine below the floor gets a legible page instead of transparent panels, every colour is an oklch value behind a custom property, which computes to `unset` rather than falling back when unsupported.

### Changed
- **Motion easing**: added `--ease-out` / `--ease-in-out` / `--ease-drawer` to the theme (usable as `ease-out`, `ease-in-out`, `ease-drawer`) and pointed `--default-transition-timing-function` at the ease-out curve. Nothing in the library used an explicit `ease-out` before, so every bare `transition` ran on Tailwind's symmetric default, which eases *in* as well, delaying the first frame, the one the user is watching. There is deliberately no `ease-in` token. `sheet` moves off `ease-in-out` (wrong for a panel that enters and exits) onto `ease-drawer`, and narrows its `transition` to transform and opacity so the glass `backdrop-filter` is no longer interpolated on every open.
- **Hover and caret timing**: `Card animated` drops 300ms → 150ms and narrows `transition` to transform and box-shadow; the `navigation-menu` caret drops 300ms → 200ms on `transition-transform`. Both were animating the full ~10-property `transition` shorthand, `backdrop-filter` included, for effects seen dozens of times a session.
- **Outrun sun on every day horizon**: `clouds`, `dune` and `aurora` now show synthwave's banded sun low on the horizon in light mode instead of a small high disc, and hand back to the moon at night. The sun moved from `SYNTHWAVE_STYLES` into the shared sky furniture; both discs render and `--sw-sun-o` / `--sw-moon-o` pick one per mode, the same way `--sw-stars-o` gates the stars. `aurora` gains a disc for the first time (day only, it stays deliberately moonless at night) and joins the sun/moon placement control.
- **`@tanstack/react-table` v8 → v9**: migrated the `data-table` block to v9's feature architecture: `useReactTable` → `useTable`, and the row models moved out of table options into a `tableFeatures()` registry (`columnFilteringFeature`, `rowSortingFeature`, `rowPaginationFeature` plus their `filteredRowModel` / `sortedRowModel` / `paginatedRowModel` slots). `getCoreRowModel()` is gone: the core row model is implicit. Types now take `TFeatures` first (`ColumnDef<typeof features, Member>`), `table.getState()` is `table.state`, and sort/filter functions are registered by name and referenced per column rather than auto-detected. Only the three features this block uses are registered, so the rest tree-shake out.
- **`CardTitle` leading**: `leading-none` → `leading-tight`. A one-line title looks identical; a title that *wraps* no longer sets its lines almost touching, which showed up on narrow cards and on mobile. Single-line title boxes grow 16px → 20px, so a card's header is 4px taller.
- **Dialog family lays out by container, not viewport**: `dialog`, `alert-dialog` and `sheet` content surfaces are now named containers (`@container/dialog-content`, `/alert-dialog-content`, `/sheet-content`), and their headers and footers respond to the surface's own width instead of the window's. A narrow dialog on a wide screen now stacks its footer and centres its header, where it previously went horizontal because the *viewport* was wide. This also removes the `sm:group-data-[size=default]/…` chains from `alert-dialog`, the CSS measures instead of being told. **Behaviour change** for any consumer rendering a constrained-width dialog or sheet; the `size="sm"` two-column button grid is unaffected. See [`docs/container-queries.md`](./docs/container-queries.md).
- **Dune ridge profiles**: replaced the all-smooth silhouettes with asymmetric ridges: a long windward flank rising to a defined apex, then a short steep slip face, 4–6 crests per tile at uneven spacing, sharpening toward the viewer.
- **Text foreground ramp**: changed the default to a linear lightness ramp to hold theme chroma and shift high-contrast text to tinted white.
- **Fresco anchor hues**: retuned Sistine, Muse Night, and Gloaming Day for better warmth and legibility.
- **Dark mode selector**: refactored to use a zero-specificity `&:where(.dark, .dark *)` selector for proper styling application.
- **Glass tint scoping**: split `:root` and `.dark` declarations so `data-glass-tint` properly scopes derived tokens to its subtree.
- **Solid glass opacity**: composed `--glass-solid-a` inside the utility class so mode lightness and opacity dials both resolve directly on the element.
- **CanvasBackground component**: added an optional `hue` prop to drive canvas color independently of the live tint.
- **Sonner toaster**: decoupled from `next-themes` by accepting a `theme` prop to make the component portable.
- **Component architecture**: converted 16 glass components to use `cva` for variant consistency.
- **Theme packaging**: components and blocks now depend on `@sistine/theme` for the CSS tokens instead of each bundling a copy of `app/globals.css`, so a fresh `add` writes the theme once (via the dependency, with its `tw-animate-css` dep) rather than dropping a redundant `globals.css` per component.
- **GradientBackground component**: added an optional `hue` prop to drive the gradient color independently of the live tint (mirrors `CanvasBackground`).
- **Component docs**: clarified that `carousel` is a single items-driven component (pass slides as `children`; no compound `CarouselContent`/`CarouselItem`/`CarouselNext`/`CarouselPrevious`/`CarouselApi`) and that `mode-toggle` requires a `next-themes` `ThemeProvider`.

### Fixed
- **Gamut safety margin**: added a 3% margin to prevent high-chroma edge colors from greying out in Safari.
- **Neutral tints**: updated to correctly produce achromatic foregrounds while keeping the hue ramp a full 360° color wheel.
- **Dialog rendering**: dropped the `relative` position class from the glass wrapper to prevent the modal from rendering off-screen.
- **Button styling**: updated `default` to keep primary fill with a glass sheen, and `secondary` to use bordered neutral glass.
- **Badge hydration**: changed the root element from `<div>` to `<span>` to resolve hydration warnings inside phrasing content.
- **Glass variants**: resolved crystal wash issues under fresco presets and dropped backdrop blur on `glass-opaque` for lossless composition.
- **input-otp types**: the base component now compiles against upstream `input-otp` types directly; removed a private module shim that masked a discriminated-union mismatch and never shipped to consumers, so `shadcn add input-otp` no longer fails to type-check.
- **Resizable dependency pin**: corrected the `react-resizable-panels` pin from `^3.0.6` to `^4.12.1` to match the v4 namespace API (`Group`/`Panel`/`Separator`) the component uses; a fresh `add` no longer installs an incompatible v3.
